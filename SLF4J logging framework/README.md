## 📖 About

This repository demonstrates the implementation of the **Simple Logging Facade for Java (SLF4J)** in a **Spring Boot** application. It showcases how to configure logging and utilize different log levels to improve application monitoring, debugging, and maintenance.

The project is developed as part of the **Cognizant Digital Nurture (DN) Program** to understand logging best practices in enterprise Java applications.

---

## 🎯 Repository Objectives

- Understand the importance of logging in Java applications.
- Configure SLF4J in a Spring Boot project.
- Implement logging using multiple log levels.
- Improve debugging and application monitoring.
- Follow logging best practices in enterprise applications.

# 📚 Exercise

## 📌 Logging with SLF4J

### Description

Implement logging in a Spring Boot application using **SLF4J** and **Logback** to record application events and execution details.

### Concepts Covered

- SLF4J Logger
- Logback Configuration
- Logging Levels
- Spring Boot Logging
- Console Logging
- Application Monitoring

---

## 📊 Logging Levels Used

| Log Level | Purpose |
|-----------|---------|
| **TRACE** | Detailed execution flow information |
| **DEBUG** | Debugging application logic |
| **INFO** | General application events |
| **WARN** | Potential issues requiring attention |
| **ERROR** | Errors and exceptions during execution |

## ▶️ How to Run

### Clone the Repository

```bash
git clone <repository-url>
```

### Navigate to the Project

```bash
cd "SLF4J Logging Framework"
```

### Run Using Maven

```bash
mvn spring-boot:run
```

Or run the main Spring Boot application class directly from your IDE.

---

## 📄 Expected Output

When the application runs, log messages similar to the following will be displayed in the console:

```text
INFO  - Application started successfully.
DEBUG - Loading application configuration.
WARN  - Configuration file not found. Using default values.
ERROR - Exception occurred while processing request.
```

> **Note:** The actual output may vary depending on the logging statements implemented in the application.
